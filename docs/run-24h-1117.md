## Findings that came first

- **Renut's record mutex on the frame chain.** The console's sampled stacks (the 15 ms build, two races): every frame-job
  worker (JQ0, JQ1, JQ2, JQ4) spends 6.6-7.3 % of its sampled time waiting in `pthread_mutex_lock` from Renut's NewOp
  (and ~0.9 % from the BeginCommandBuffer hook), Game Master 1.2 %. NewOp's lock-free memo was invalidated globally: one
  generation bumped by every BeginRecording / ReleaseCommandBuffer / new buffer anywhere, and one pending-vertices count
  for all devices. Fixed: a hashed generation per command buffer and a pending count per device
  (`blur_renut_record_memo_local`, on). Scratchpad wait_census.py: the waits of each frame-chain thread by site.
- **Game Master's sleep in the input read.** 11.7 % of Game Master's sampled time is `nanosleep` inside
  rex::input::InputSystem::GetState: the late-input delay (`banjo_late_input`, rex::latency::BeforeInputRead), which
  moves the frame's first controller read later by the slack it measures at Swap. The A/B (late input off) is in the
  console sequence of the night.
- **The machine waits on memory.** tools/codegen_census.py samples (the 15 ms build): 56.5 % of all console samples sit
  on loads (14.4 % on guest loads through the 32-bit index), stores 15 %, integer work 15 %, float / vector 10 %, byte
  swaps 0.6 %, system instructions (flush-mode switches) 0.9 %. What is left to win is in waits (locks, sleeps) and in
  cache misses (pointer chases), not in the generated code's instruction count: the codegen ideas that remove
  instructions (#228, #229, #213, #234, #235) were measured or reasoned out by that.
- **Guest memory in large blocks (#189 of the earlier list):** already in the base (guest_memory_switch.cpp commits
  2 MB-aligned chunks so Horizon maps them with block descriptors).
- **The indirect-call dispatch table misses.** 0.4-0.5 % of all console samples (1.6-3.3 % of JQ Worker 3's) sit on the
  one load of REX_LOOKUP_FUNC (a 20 MB table). CG-08 built: a one-entry cache per call site.
